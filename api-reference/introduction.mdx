The Kith Workspace API allows you to interact with your workspace programmatically. You can manage bans, sessions, staff activity, and more directly from your own applications or Roblox game servers.

## Base URL

All API requests should be made to the following base URL:

```text
https://api.lumonol.co.uk
```

## Authentication

All endpoints require authentication using a **Workspace ID** and a **Bearer Token** (API Key).

You must pass the Workspace ID as a query parameter (or in the JSON body) and your API Key in the `Authorization` header.

```bash
curl -X GET "https://api.lumonol.co.uk/bans?workspace_id=YOUR_WORKSPACE_ID" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

<Warning>
  Your API keys carry high privileges within your workspace. Keep them secure and never expose them in client-side code.
</Warning>

### Generating API Keys

API Keys are generated from your Dashboard under **Workspace Settings > Developer API**. 
Each key is strictly scoped to its specific Workspace.

## Content Type

For `POST` and `PATCH` requests, you must include the `Content-Type: application/json` header and format your request body as JSON.

## Response Format

All responses are returned as JSON. Successful requests will generally return a `200 OK` status code with the requested data.

### Errors

If a request fails, the API will return a standard HTTP error code (such as `400 Bad Request` or `401 Unauthorized`) along with a JSON response containing an `error` message detailing what went wrong.

```json
{
  "error": "No fields to update provided."
}
```
